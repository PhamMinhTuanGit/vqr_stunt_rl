# VQR pose optimization — M-TO0 model audit

This directory currently implements **M-TO0 only**. It does not contain
kinematic optimization, CasADi, IPOPT, contact-force optimization, RNEA
equilibrium constraints, RL, or trajectory optimization.

## Model provenance

The trace required by the repository is:

1. `source/rl_training/rl_training/tasks/manager_based/locomotion/pivot/config/wheeled/vqr/robot_cfg.py`
   constructs its asset from
   `deep_robotics_model/VQRWheel/VQRWheel_usd/VQRWheel.usd`.
2. `deep_robotics_model/VQRWheel/VQRWheel_usd/config.yaml`, generated by the
   Isaac Lab `UrdfConverter`, records the source asset as
   `deep_robotics_model/VQRWheel/VQRWheel_urdf/urdf/VQRWheel.urdf`.
3. M-TO0 therefore reuses this existing URDF in place:

   ```text
   ../deep_robotics_model/VQRWheel/VQRWheel_urdf/urdf/VQRWheel.urdf
   ```

The CMake file resolves that repository-relative path to an absolute canonical
path and compiles it into the audit executable. No URDF is copied or modified.
At run time the executable also checks that `robot_cfg.py` still names the same
USD and that its converter metadata still names this URDF.

## Build and run

From this directory:

```bash
cmake -S . -B build
cmake --build build -j
./build/model_audit
ctest --test-dir build --output-on-failure
```

The build first uses a normally discoverable Pinocchio package. It also detects
the `cmeel.prefix` layout used by the project's installed Pinocchio wheel, so
the commands above do not need a machine-specific `CMAKE_PREFIX_PATH` here.

## Audited conventions

- Pinocchio loads the URDF with a free-flyer root. Its configuration ordering is
  printed with `idx_q/nq` and `idx_v/nv`; this differs from Isaac Lab's explicit
  runtime articulation ordering.
- The stance set is `FL, HR`; the swing set is `FR, HL`.
- `FL_WHEEL`, `FR_WHEEL`, `HL_WHEEL`, and `HR_WHEEL` are selected specifically
  as Pinocchio `BODY` frames. A same-named joint frame also exists, so selecting
  by name without a frame type would be ambiguous.
- Each wheel link has one cylinder collision of radius `0.091 m`, whose origin
  is `[0, 0, 0]` in the wheel link. The selected BODY frames are consequently
  **wheel-center frames**, not ground-contact frames. The URDF defines no
  explicit ground-contact frame.
- The URDF provides `60 Nm` effort limits for all 12 leg joints. Its four
  continuous wheel joints have neither angular position limits nor effort
  limits. The Isaac Lab actuator config separately applies `20 Nm` to wheels;
  this is repository configuration, not a URDF/hardware limit.

## Nominal state and audit result

The nominal state is taken from `VQR_CFG.init_state` and `DEFAULT_JOINT_POS`:
base position `[0, 0, 0.45] m`, identity base quaternion, HipX `0`, HipY
`-0.65 rad`, knee `1.3 rad`, and wheel angle `0`. The executable maps these
values by exact joint name so it does not confuse Isaac Lab and Pinocchio joint
ordering. This is also the state explicitly exposed as `STANDING_JOINT_POSITIONS`
by `four_to_two_rotate_env_cfg.py`. The separate M1 balance reset folds FR and HL
to HipY `-1.0 rad` and knee `2.0 rad`; that task-specific two-wheel reset is not
the repository's default standing pose and is therefore not substituted into
this M-TO0 nominal-standing audit.

The verified Pinocchio model has `nq = 27`, `nv = 22`, and total mass
`32.86 kg`. Its joint ordering is:

The four continuous wheel angles use Pinocchio's normalized
`[cos(theta), sin(theta)]` representation, which accounts for `nq - nv = 5`

At the repository nominal state, Pinocchio reports:

```text
CoM xyz [m] = [-0.010210449,  0.000000000, 0.372753955]
FL center [m] = [ 0.249005186,  0.236500000, 0.086164386]
FR center [m] = [ 0.249005186, -0.236500000, 0.086164386]

HR center [m] = [-0.247794814, -0.236500000, 0.086164386]
```

The nominal center height is about `4.84 mm` below the collision radius. That
does not change the audited convention: these are wheel-center BODY frames, and
the repository's nominal base height is not being altered in M-TO0.

The executable and CTest both pass all required checks: provenance, URDF load,
positive mass, finite CoM, finite FK, four BODY frames, readable joint limits,
and a finite normalized nominal Pinocchio configuration within bounded-joint
limits.

## Remaining model limitation

There is no ambiguity in the audited URDF source, joint ordering, actuator
mapping, wheel radius, or selected frame convention. There is, however, no
explicit ground-contact frame in the URDF; later work must derive a contact
point from the wheel-center frame and geometry. Also, `20 Nm` for each wheel is
an Isaac Lab actuator setting only—the URDF supplies no wheel effort limit, so
it is not independently established as a hardware torque rating.
